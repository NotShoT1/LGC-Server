📌 Règles de fonctionnement

  • Aucun mod en production sans validation préalable sur le serveur de test.
  • Chaque déploiement est suivi de 3 à 5 jours de surveillance intensifiée.
  • Le passage d'une phase à l'autre est soumis à un vote staff (jalons Go/No-go).
  • Les mods abandonnés ou instables sont archivés lors de la revue mensuelle.
  • La communauté propose, le staff valide — rythme cible : 1 vague/mois.
📋
J-14 · Audit du catalogue de mods
Phase : Pré-lancement · Semaine −2 · Responsables : Toute l'équipe staff
🎯
Objectif : Constituer un package de base solide pour le lancement. Identifier clairement quels mods sont prêts pour la production et lesquels doivent passer par le serveur de test.

✅ Tâches

Technique

  • Lister l'intégralité des mods du catalogue dans un tableau partagé
  • Configurer le serveur de test sur une instance séparée (port distinct, liste de mods indépendante)
  • Vérifier que les mods du package de base se chargent sans erreur sur le serveur de test

Revue

  • Remplir la grille de classification pour chaque mod (voir ci-dessous)
  • Geler la liste du package de base — aucune modification après ce jalon

📊 Grille de classification des mods

Notez chaque mod de 0 à 2 sur chacun des 5 critères :

✔️ Critères de validation du jalon

  • Tous les mods du catalogue ont été classés
  • Le package de base est gelé et validé par au moins 2 membres du staff
  • Le serveur de test est opérationnel
  • La liste des mods "à tester" et "à risque" est documentée

J-7 · Tests internes staff
Phase : Pré-lancement · Semaine −1 · Responsables : Staff joueurs + admin technique
🎯
Objectif : Valider le package de base en conditions réelles avec l'équipe staff. Corriger les derniers bugs bloquants. Préparer la communication d'ouverture.

✅ Tâches

Test interne

  • Organiser au minimum 2 sessions de jeu complètes sur le serveur de test
  • Tester des scénarios variés : connexion/déconnexion, longue session, redémarrage serveur
  • Documenter tous les bugs observés dans un rapport partagé

Technique

  • Trier les bugs remontés : bloquants / mineurs / cosmétiques
  • Corriger tous les bugs bloquants avant J0
  • Effectuer un dernier test de charge (plusieurs connexions simultanées)

Comms

  • Rédiger et publier l'annonce de lancement (Discord, forum)
  • Préciser la date et l'heure d'ouverture
  • Présenter brièvement le gamemode et le package de mods aux joueurs
  • Ouvrir un canal dédié aux retours et bugs pour le lancement

✔️ Critères de validation du jalon

  • Au moins 2 sessions de test réalisées avec compte-rendu
  • Zéro bug bloquant restant à J0
  • L'annonce d'ouverture est publiée au moins 48h avant J0
  • Le canal de retours joueurs est prêt
⭐
J0 · Ouverture publique
Phase : Lancement · Jour J · Présence staff obligatoire
🎯
Objectif : Ouvrir le serveur dans les meilleures conditions. Détecter immédiatement tout problème critique et rassurer la communauté par une présence staff visible.

✅ Tâches

Monitoring

  • Surveiller les logs serveur en continu les 3 premières heures
  • Vérifier les performances : CPU, RAM, latence, taux de tick
  • Identifier tout crash ou déconnexion anormale (noter heure et contexte)
  • Surveiller les conflits de mods visibles en jeu

Comms

  • Être présent sur Discord pour répondre aux premières questions joueurs
  • Confirmer publiquement que le serveur est ouvert et opérationnel
  • Épingler les instructions de rapport de bugs dans le canal dédié

Revue

  • Tenir un debrief staff en fin de soirée J0
  • Mettre à jour le tableau de suivi des bugs

🚨 Procédure en cas de crash critique

  • Notifier immédiatement le staff sur le canal interne
  • Communiquer aux joueurs (message Discord) : contexte + ETA de résolution
  • Redémarrer le serveur si nécessaire
  • Identifier le mod responsable dans les logs
  • Désactiver temporairement le mod incriminé si pas de correction rapide possible
  • Documenter l'incident

✔️ Critères de validation

  • Le serveur est resté stable pendant au moins 3h consécutives
  • Le debrief J0 a eu lieu
  • Les bugs critiques sont documentés et assignés
⚖️
J+14 · Bilan de stabilité — Go / No-go
Phase : Fin lancement · Décision collective · Toute l'équipe staff
🎯
Objectif : Évaluer objectivement la stabilité du serveur après 2 semaines de live. Décider si le serveur est prêt pour accueillir de nouveaux mods.

✅ Tâches

Monitoring

  • Compiler le nombre de crashes sur la période J0→J+14
  • Calculer le taux de disponibilité du serveur (uptime)
  • Analyser les logs : erreurs récurrentes liées à un mod spécifique ?
  • Rassembler les retours joueurs du canal dédié

Revue

  • Rédiger la synthèse de stabilité
  • Présenter la synthèse à l'ensemble du staff
  • Voter collectivement : Go ou No-go
  • Documenter la décision et la justification

🔀 Résultat du vote

✅
GO → Passage en Phase 3 · Lancement du serveur de test Lot 1 (→ J+21)
❌
NO-GO → Prolongation Phase 2 de 1 semaine · Nouveau bilan à J+21

✔️ Critères pour un GO

  • Moins de 3 crashes non résolus sur la période
  • Uptime > 95%
  • Aucun bug bloquant en suspens
  • Ressenti joueurs globalement positif

J+21 · Serveur de test — Lot 1
Phase : Intégration progressive · Semaines 3–4 · Admin technique + staff volontaires
🎯
Objectif : Valider les premiers mods classés "à tester". Tester leur comportement seuls puis combinés au package de production, avant tout déploiement en live.

✅ Tâches

Test interne

  • Sélectionner les mods prioritaires à tester dans ce lot
  • Tester chaque mod seul : chargement, stabilité, comportement de base
  • Tester chaque mod combiné au package de production complet
  • Documenter les interactions entre mods (conflits, perfs, comportements inattendus)
  • Organiser au moins 1 session jouée avec le staff volontaire par mod retenu

Revue

  • Remplir la grille de validation pour chaque mod testé
  • Classer les mods en : Validé / À retravailler / Écarté
  • Préparer la liste des mods retenus pour la Vague 1 (→ J+30)

J+30 · Vague 1 — Déploiement
Phase : Intégration progressive · Mois 1 · Admin technique + Staff communication
🎯
Objectif : Déployer en production les mods validés lors du Lot 1. Communiquer la nouveauté à la communauté. Surveiller la stabilité de près dans les jours qui suivent.

✅ Tâches

Déploiement

  • Ajouter les mods validés à la liste de production du serveur
  • Effectuer un redémarrage serveur propre avec le nouveau package
  • Vérifier le chargement complet sans erreur au premier démarrage
  • Tester une connexion rapide en jeu avant l'annonce publique

Comms

  • Rédiger le changelog de la Vague 1
  • Publier l'annonce sur Discord avec le changelog
  • Épingler le message dans le canal approprié

Monitoring

  • Surveillance intensifiée pendant les 3 à 5 premiers jours post-déploiement
  • Logs analysés quotidiennement sur cette période
  • Canal de retours bugs actif et surveillé

J+60 · Rythme long terme
Phase : Long terme · À partir du 2e mois · Cycle mensuel récurrent
🎯
Objectif : Installer un cycle régulier test → validation → déploiement. Maintenir l'intérêt des joueurs dans la durée en proposant des nouveautés régulières.

🔁 Le cycle mensuel

Semaine 1 : Vote communauté sur les prochains mods Semaine 2 : Tests sur serveur de test (lot suivant) Semaine 3 : Validation + préparation du déploiement Semaine 4 : Déploiement + annonce + surveillance

✅ Tâches récurrentes chaque mois

Déploiement

  • Déployer la vague du mois (mods validés lors de la semaine de test)
  • Annoncer la vague à l'avance (J-7 avant déploiement)
  • Publier le changelog

Revue mensuelle du package

  • Vérifier le statut de chaque mod en production : toujours maintenu ? Mis à jour ?
  • Identifier les mods abandonnés (> 3 mois sans MAJ, issues sans réponse)
  • Proposer au staff le retrait ou remplacement des mods obsolètes
  • Archiver les mods retirés avec une note explicative

Comms

  • Lancer le sondage communautaire en début de mois
  • Annoncer les résultats du vote et ce qui sera testé ce mois-ci
  • Communiquer sur le retrait d'un mod si nécessaire
